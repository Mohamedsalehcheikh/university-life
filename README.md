# حياتي الجامعية

تطبيق شخصي لإدارة الحياة الجامعية لطالب سنة ثانية إلكتروتقني. التطبيق مبني بـ **React + Vite + Capacitor**، ويستخدم تخزين الهاتف للعمل دون اتصال، مع طبقة Supabase اختيارية للمزامنة والحساب الشخصي. الواجهة عربية بالكامل واتجاهها من اليمين إلى اليسار، وتدعم الوضع الداكن.

## ما الذي يتضمنه المشروع؟

| القسم | الوظيفة |
|---|---|
| الرئيسية | ملخص حصص اليوم، أقرب واجب، أقرب امتحان، والمعدل الحالي |
| الجدول | حصص CM وTD وTP بحسب أيام الأسبوع مع تمييز الحصة الأولى/القريبة |
| المقاييس | تعديل النقاط والمعاملات يدوياً |
| المعدل | حساب المعدل على 20 بالمعاملات ومحاكاة اختيار مقياس |
| المهام | قائمة يومية، واجبات ومشاريع، تاريخ تسليم، حذف وإنجاز |
| التنبيهات | جدولة تنبيه محلي للواجب عبر Capacitor Local Notifications |
| المظهر | Dark Mode محفوظ على الهاتف |

البيانات الأساسية التجريبية موجودة في `src/main.tsx` ويمكن تعديلها من داخل التطبيق. بيانات المقاييس والمهام تُحفظ في `localStorage`، لذلك يستمر التطبيق في العمل بلا إنترنت. توجد ملفات Supabase الجاهزة لإضافة حساب شخصي ومزامنة البيانات عند الحاجة.

## هيكل المشروع

```text
university-life/
├── .github/workflows/build-apk.yml
├── src/main.tsx
├── src/styles.css
├── src/supabase.ts
├── capacitor.config.ts
├── package.json
├── vite.config.ts
├── tsconfig.json
├── .env.example
└── supabase-schema.sql
```

لا ترفع مجلد `android` يدوياً. ملف Workflow ينشئ منصة Android تلقائياً أثناء البناء، وهذا يقلل حجم المستودع ويجنب مشاكل الملفات المولدة.

## رفع المشروع من تطبيق GitHub على Samsung A15

### 1. إنشاء مستودع خاص

افتح تطبيق GitHub، اضغط علامة **+**، ثم اختر **New repository**. اكتب اسماً مثل `university-life`، فعّل **Private**، ثم اضغط **Create repository**. لا تحتاج إلى إضافة README من GitHub لأن المشروع يحتوي على README جاهز.

### 2. رفع الملفات

داخل المستودع الجديد، اضغط **Add file** ثم **Upload files**. من تطبيق الملفات على هاتف Samsung افتح المجلد الذي فككت فيه ملفات المشروع، وحدد الملفات والمجلدات التالية:

- `src`
- `.github`
- `package.json`
- `capacitor.config.ts`
- `vite.config.ts`
- `tsconfig.json`
- `index.html`
- `.env.example`
- `supabase-schema.sql`
- `README.md`

إذا لم يظهر مجلد `.github` في منتقي الملفات، فعّل إظهار الملفات المخفية في تطبيق **ملفاتي**، أو ارفع ملف `build-apk.yml` من خلال خيار إنشاء ملف جديد داخل GitHub بالمسار `.github/workflows/build-apk.yml`.

بعد اختيار الملفات، اكتب رسالة مثل `initial university app` واضغط **Commit changes**. تأكد أن الفرع اسمه `main` أو `master`؛ كلاهما مدعوم في Workflow.

> لا ترفع ملف `.env` الذي يحتوي مفاتيح حقيقية. ملف `.env.example` مجرد نموذج، والمفتاح العام لـ Supabase ليس كلمة مرور، لكن لا تضع أي مفتاح سري أو service role key داخل تطبيق الهاتف.

## تشغيل البناء وتحميل APK

1. افتح تبويب **Actions** داخل المستودع.
2. وافق على تفعيل Workflows إذا طلب GitHub ذلك.
3. افتح **Build Android Debug APK**.
4. اضغط **Run workflow** إذا أردت تشغيله يدوياً، ثم اختر `main` واضغط زر التشغيل. كما سيبدأ البناء تلقائياً بعد كل `push`.
5. انتظر حتى تتحول المهمة إلى علامة نجاح خضراء. عند الفشل افتح خطوة الفشل واقرأ سجلها.
6. افتح نتيجة التشغيل الناجح، ثم انزل إلى قسم **Artifacts**.
7. اضغط `university-life-debug-apk` ليُحمّل ملف ZIP.
8. افتح ZIP من تطبيق **ملفاتي**، ثم استخرج الملف `app-debug.apk` إلى مجلد التنزيلات.

هذا APK هو **debug APK** قابل للتثبيت يدوياً. لا يحتاج keystore ولا حساب Google Play ولا توقيع نشر. عند تثبيت نسخة أحدث، قد يطلب الهاتف استبدال النسخة القديمة؛ وافق على التحديث إذا كان معرّف التطبيق نفسه.

## Supabase للحساب الشخصي والمزامنة الاختيارية

لا تحتاج Supabase لكي يعمل الإصدار المحلي الحالي. إذا أردت حفظ نسخة سحابية:

1. افتح `supabase.com` من متصفح الهاتف وأنشئ مشروعاً خاصاً.
2. من **SQL Editor** شغّل محتوى `supabase-schema.sql`.
3. من **Authentication > Providers** اترك Email مفعلاً.
4. أنشئ حساباً واحداً بالبريد الإلكتروني الذي تستخدمه.
5. انسخ **Project URL** و**anon public key** إلى متغيرات البيئة في بيئة البناء باسم `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY`.

ملف `src/supabase.ts` يوفر عميل Supabase ودوال تسجيل الدخول والخروج. سياسة قاعدة البيانات تمنع أي مستخدم من قراءة بيانات مستخدم آخر. لأسباب أمنية، لا تضع `service_role` key في GitHub أو داخل APK.

## تفعيل التنبيهات داخل التطبيق

في أول مرة تضغط جرس مهمة، سيطلب Android إذن الإشعارات. اضغط **سماح**. اختر المهمة ثم اضغط أيقونة الجرس لكي يُجدول تنبيه عند تاريخ التسليم الساعة 09:00. إذا كان تاريخ المهمة قديماً فلن يظهر تنبيه مستقبلي؛ عدّل التاريخ في الإصدار اللاحق أو أضف المهمة بتاريخ قادم.

## تثبيت APK على Samsung A15

1. افتح **الإعدادات**.
2. ادخل إلى **الأمان والخصوصية**.
3. اختر **المزيد من إعدادات الأمان**.
4. اضغط **تثبيت تطبيقات غير معروفة**.
5. اختر التطبيق الذي فتحت به APK، مثل **Chrome** أو **ملفاتي**.
6. فعّل **السماح من هذا المصدر**.
7. افتح `app-debug.apk` من مجلد **التنزيلات**.
8. وافق على التثبيت، ثم أوقف خيار **السماح من هذا المصدر** بعد الانتهاء لأمان أفضل.

قد تختلف أسماء القوائم قليلاً حسب إصدار One UI. إذا ظهر تحذير بأن التطبيق غير معروف، تحقق من أنك حملت الملف من Artifact داخل مستودعك الخاص، ثم تابع التثبيت يدوياً. لا تشارك رابط Artifact أو APK مع الآخرين لأن التطبيق مصمم للاستعمال الشخصي.

## تشغيل محلي اختياري

إذا احتجت اختبار الواجهة في خدمة تطوير، نفّذ من بيئة Node:

```bash
npm install
npm run dev
```

لبناء Android يدوياً خارج GitHub Actions:

```bash
npm install
npm run build
npx cap add android
npx cap sync android
cd android
./gradlew assembleDebug
```

لكن لا تحتاج إلى تنفيذ هذه الأوامر من الهاتف؛ Workflow هو المسار المقصود لك.

## ملاحظات مهمة

التطبيق الحالي يقدّم بيانات ابتدائية نموذجية للجدول والامتحانات. عدّلها في `src/main.tsx` إذا أردت جدولاً مختلفاً، ثم ارفع التعديل إلى GitHub ليُبنى APK جديد. نسخة debug مخصصة للتثبيت الشخصي وليست للنشر العام. لا تحذف بيانات التطبيق من إعدادات الهاتف إلا إذا كنت تملك نسخة احتياطية، لأن بيانات `localStorage` تُحذف عند مسح بيانات التطبيق.
